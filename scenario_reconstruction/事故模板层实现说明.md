# 事故模板层实现说明

当前已经完成的第一步：把 Autoware 故障事故抽象成项目可读取、可校验、后续可接入 SUMO/NADE 仿真的“事故模板”。

## 1. 实现目标

这一阶段的目标是建立一个中间层：

```text
Autoware 故障事故信息
        ↓
事故模板 YAML
        ↓
模板解析与校验
        ↓
后续用于 SUMO/NADE 场景初始化
```

这么做的原因是：Autoware 的 `.db3` 是原始运行日志，而 D2RL 训练需要的是本项目仿真环境重新生成的 episode JSON。中间必须先把现实事故抽象成可复现的仿真场景，例如自车在哪里、速度多少、关键背景车在哪里、何时 cut-in、故障何时发生。

## 2. 新增文件

当前新增了以下文件：

```text
scenario_reconstruction/
  __init__.py
  README.md
  templates.py
  validate_template.py
  templates/
    autoware_cut_in.yaml
```

各文件作用如下：

```text
templates.py
```

定义事故模板的数据结构、读取逻辑和校验规则。

```text
templates/autoware_cut_in.yaml
```

一个示例事故模板，描述两车道高速 cut-in 场景。它可以作为后续从 Autoware 故障数据重建事故的第一版模板。

```text
validate_template.py
```

命令行校验工具，用来检查某个 YAML 模板是否能被解析、字段是否完整、数值是否满足当前仿真约束。

```text
README.md
```

英文简要说明，方便之后继续开发时快速知道这个目录的用途。

```text
__init__.py
```

把 `ScenarioTemplate` 和 `load_template` 暴露为模块接口，方便后续其它代码直接导入。

## 3. 模板数据结构

事故模板用 YAML 描述。当前示例文件是：

```text
scenario_reconstruction/templates/autoware_cut_in.yaml
```

它的顶层字段包括：

```yaml
template_id: autoware_cut_in_run01
description: ...
map: 2Lane
route: route_0
duration: 12.0
tags: [...]
ego: ...
actors: ...
events: ...
perturbations: ...
```

### 3.1 `template_id`

模板 ID，用来唯一标识一个事故模板。

示例：

```yaml
template_id: autoware_cut_in_run01
```

后续做批量生成时，可以用它作为输出目录、日志前缀或实验名称的一部分。

### 3.2 `description`

模板说明。它不参与仿真，只帮助人理解这个模板代表什么事故。

当前示例说明的是：关键背景车从右侧车道切入 CAV 所在车道。

### 3.3 `map`

仿真地图名称。

当前只支持：

```yaml
map: 2Lane
```

原因是当前项目主入口 `main.py` 使用的是：

```text
maps/2LaneHighway/2LaneHighway.net.xml
maps/2LaneHighway/2LaneHighwayHighSpeed.sumocfg
```

所以模板校验里暂时限制 `map` 必须是 `2Lane`。

### 3.4 `route`

SUMO route ID。

当前项目默认车辆使用：

```yaml
route: route_0
```

### 3.5 `duration`

场景期望持续时间，单位是秒。

示例：

```yaml
duration: 12.0
```

校验规则要求它必须大于 0。事件的结束时间也不能超过这个 duration。

### 3.6 `ego`

自车 CAV 的初始状态。

示例：

```yaml
ego:
  id: CAV
  role: CAV
  route: route_0
  lane_index: 1
  position: 400.0
  speed: 34.8
  controller: IDM
```

字段含义：

```text
id
```

车辆 ID。当前项目约定自车 ID 是 `CAV`。

```text
role
```

车辆角色。自车为 `CAV`。

```text
route
```

车辆路线，当前使用 `route_0`。

```text
lane_index
```

初始车道索引。当前两车道场景只允许 `0` 或 `1`。

```text
position
```

车辆在道路上的初始纵向位置，单位是米。

```text
speed
```

初始速度，单位是 m/s。

```text
controller
```

车辆控制器。当前自车示例使用 `IDM`，和项目默认 AV model 对齐。

### 3.7 `actors`

背景车列表，表示事故里关键的其他车辆。

示例：

```yaml
actors:
  - id: BV_cut_in
    role: BV
    route: route_0
    lane_index: 0
    position: 418.0
    speed: 24.5
    controller: script
  - id: BV_right_follower
    role: BV
    route: route_0
    lane_index: 0
    position: 388.0
    speed: 23.5
    controller: IDM
```

当前示例里有两个背景车：

```text
BV_cut_in
```

事故关键车，从右侧车道向 CAV 所在车道切入。

```text
BV_right_follower
```

右侧后方背景车，用来保持事故场景的交通上下文。

`controller: script` 表示后续会用模板里的事件强制控制该车，例如执行 cut-in 动作。这个阶段只是记录该意图，还没有实现动作执行。

### 3.8 `events`

事件列表，用来描述事故触发动作或故障注入。

当前支持的事件类型定义在 `templates.py` 的 `VALID_FAILURE_TYPES`：

```python
VALID_FAILURE_TYPES = {
    "perception_dropout",
    "perception_delay",
    "perception_position_bias",
    "control_delay",
    "forced_bv_action",
}
```

当前示例：

```yaml
events:
  - type: forced_bv_action
    actor: BV_cut_in
    start_time: 0.0
    duration: 1.0
    params:
      lateral: left
      longitudinal: 0.0
  - type: perception_dropout
    actor: BV_cut_in
    start_time: 0.0
    duration: 0.5
    params:
      target: CAV
```

第一个事件：

```text
forced_bv_action
```

表示强制 `BV_cut_in` 在 `0.0s` 开始执行一个持续 `1.0s` 的动作：

```yaml
lateral: left
longitudinal: 0.0
```

也就是向左变道，纵向加速度为 0。

第二个事件：

```text
perception_dropout
```

表示在 `0.0s` 到 `0.5s` 之间，对 `CAV` 注入一个关于 `BV_cut_in` 的感知丢失事件。

当前阶段只定义和校验这个事件，不实际修改感知结果。后续实现仿真接入时才会决定这个事件如何作用到环境里。

### 3.9 `perturbations`

扰动范围，用来把一个事故种子扩展成多条训练 episode。

示例：

```yaml
perturbations:
  - field: ego.speed
    distribution: uniform
    low: -2.0
    high: 2.0
  - field: actors.BV_cut_in.position
    distribution: uniform
    low: -5.0
    high: 5.0
```

含义是：后续批量生成时，可以在原始模板基础上对某些字段加随机扰动。

当前只支持：

```yaml
distribution: uniform
```

并且要求：

```text
low <= high
```

这个阶段只校验扰动配置是否合理，还没有实际生成扰动样本。
