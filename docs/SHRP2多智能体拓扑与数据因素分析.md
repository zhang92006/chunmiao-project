# SHRP2 多智能体拓扑与数据因素分析

## 结论

当前碰撞稀缺不是单一的数据集问题，也不是单一的算法问题，而是数据域、场景映射、仿真控制和采样策略共同造成的结果。

这些因素不需要全部“消灭”。有些是必须修正的工程问题，有些是研究对象本身，例如自然碰撞稀缺；还有一些需要通过明确研究范围来处理。

当前最关键的判断是：

> 样本数量损失主要来自速度域不匹配，碰撞类型损失主要来自两车道直路和上游筛选偏差。

## 一、哪些因素必须解决

| 因素 | 是否必须解决 | 处理方式 |
|---|---|---|
| importance weight 跨度过大 | 正式训练前必须 | 增加 log-weight，检查归一化、裁剪和有效样本量，避免少数轨迹支配训练 |
| 碰撞只来自少数事件 | 必须改善 | 扩大独立 SHRP2 源事件，而不是只增加同一事件的重复次数 |
| 训练/验证/测试按事件隔离 | 必须 | 同一个 SHRP2 事件生成的所有反事实只能进入同一个 split |
| 多车联合控制不连续 | 必须 | 保证 episode 中长期存在至少两个可控 BV，并记录有效联合决策步数 |
| 映射真实性无法量化 | 必须 | 为每个场景增加映射质量等级、支持的拓扑类型和被修改的几何量 |
| NearCrash 不一定重放成碰撞 | 不需要“修复” | 将 SHRP2 定义为真实条件锚点，而不是碰撞轨迹标签 |
| 自然碰撞概率低 | 不应消除 | 用发生器提高采样效率，并用 p/q 权重校正 |
| 低速 SHRP2 与高速 D2RL 不匹配 | 需要做范围选择 | 当前先保留高速域；后续单独建立低速模型，不能直接混用 |

## 二、两车道直路是否适合多智能体

“车道数量”和“智能体数量”不是一回事。两条车道里可以有很多车辆。

当前系统实际上是：

- 1 辆 CAV；
- 2 辆受联合策略控制的 BV；
- 因此是三车交互、两个对抗智能体。

所以两车道直路足以支持第一阶段多智能体研究，例如：

- 前车急刹；
- 邻车封堵换道；
- 前车与邻车协同；
- 两辆 BV 联合改变 CAV 的避险空间；
- 追尾和部分换道侧碰。

它适合做高速公路场景下的基础验证和消融实验，但不适合作为“通用多车碰撞重建”的唯一地图。

## 三、两车道造成的损失

需要区分“数量损失”和“碰撞模式损失”。

### 3.1 数量损失主要不是两车道造成的

在 1484 个自适应种子中，最终只有 74 个模板。1410 个被桥接器阻断的主要原因是：

- 1371 个属于速度超出当前 D2RL 高速域；
- 26 个属于初始间距范围不合适；
- 约 13 个明确属于转弯、行人、停放车辆等拓扑不支持。

因此，在桥接阶段，最大数量瓶颈是当前 `20–40 m/s` 的高速域，而不是两车道本身。

但是这个统计低估了拓扑影响，因为上游已经要求 primary BV 与 CAV 近似同车道。3043 个质量合格事件到 1484 个种子的过程中，至少 517 个因为 primary 不满足同车道关系被排除。很多交叉、转向和横向冲突在进入桥接器之前就已经被筛掉了。

### 3.2 碰撞模式损失明显受到两车道影响

两车道直路无法合理表达：

- 对向转弯；
- 路口横穿；
- 并行方向转入；
- 停放车辆遮挡；
- 行人与非机动车冲突；
- 道路曲率和路口视距；
- 左右两侧同时封堵；
- 三辆以上 BV 的包围、连锁制动和串联碰撞。

它还可能引入两类映射偏差：

1. 把原本不同道路或不同方向的车辆强行投影到同一直路，制造虚假冲突；
2. 删除原始转弯路径和横向运动，使本来可能发生的碰撞消失。

因此，当前两车道地图不会让“多智能体”失效，但会让多智能体碰撞类型集中在追尾和邻车封堵上。

## 四、下一步工作顺序

### 第一步：保留当前两车道作为基线

当前两车道结果应固定为 `Freeway-2Lane-v1` 基线。已有证据包括：

- 150/150 次运行产生了双 BV 联合训练记录；
- 得到 9 条训练可用碰撞；
- 发现了 2 个独立碰撞源事件；
- 相关联合 proposal 可以稳定运行。

后续地图和发生器都应与该基线比较，而不是直接替换基线。

### 第二步：解决正式训练的权重问题

当前碰撞样本的 importance weight 跨度极大，已有 9 条碰撞的全局有效样本量约为 1.704，最大一条轨迹占归一化权重约 72.6%。正式训练前应：

- 全程记录 `log(p/q)`；
- 避免连乘下溢；
- 统计每批数据的 ESS；
- 按源事件分层采样；
- 明确训练中使用原始、归一化还是受控裁剪权重；
- 保留未裁剪权重用于最终概率估计。

### 第三步：增加三车道高速公路拓扑

下一张地图建议是三车道直路，而不是立即做复杂城市路口。三车道仍与原始高速 D2RL 行为模型一致，同时可以支持：

- 左右两侧逃逸；
- 左、右 BV 同时封堵；
- primary + 两个 context BV；
- K=2 与 K=3 的多智能体消融；
- 更丰富的切入、追尾和协同换道。

建议先在三车道中保持两个受控 BV，确认接口稳定后再扩展到三个 BV。这样可以避免地图变化和智能体数量变化同时发生，便于解释性能差异。

### 第四步：建立按冲突类型分配的拓扑路由

不要把所有 SHRP2 数据强行塞进一张地图。建议建立如下映射：

| SHRP2 冲突类型 | 推荐拓扑 |
|---|---|
| `leading/rear-end` | 两车道或三车道高速路 |
| `lane change/cut-in` | 三车道高速路 |
| `turning across opposite` | 四岔路口 |
| `turning into parallel/opposite` | 路口拓扑 |
| `pedestrian/parked` | 城市道路，作为后续独立研究 |

每个种子应增加：

- `required_topology`；
- `mapping_fidelity_grade`；
- `geometry_modified`；
- `unsupported_reason`。

## 五、研究范围建议

如果论文目标是“真实危险场景条件下的高速公路多智能体稀有事件生成与 D2RL 训练”，两车道基线加三车道扩展是合理的，不必立刻覆盖路口、行人和所有 SHRP2 类型。

如果论文要声称“通用 SHRP2 碰撞重建”，两车道直路明显不够，至少还需要路口拓扑。

因此推荐顺序是：

1. 修正并验证训练权重；
2. 完成两车道上的 proposal 消融；
3. 增加三车道高速地图；
4. 比较同一批种子在两车道和三车道下的碰撞保留率；
5. 再决定是否把路口拓扑纳入本篇论文。
