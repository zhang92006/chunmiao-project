# 高冲突潜力场景标签

本阶段只完成碰撞可达性路线的第一步：依据原始 highD 轨迹建立可审计的高冲突潜力标签。标签用于离线场景挖掘，不是事故真值，也不是在线风险预测结果。

## 标签定义

场景必须同时满足以下预注册条件：事件时 THW 不超过 2.0 s；CAV 相对换道车的接近速度至少为 0.1 m/s；换道车在事件时位于 CAV 前方；观察前缀后存在车身横向重叠；从 1.0 s 观察前缀结束到首次横向重叠至少有 0.2 s 可干预时间；横向重叠期间的最小纵向车框间距不超过 15 m。

这些阈值保存在 `configs/conflict_diagnostics.json`。分类使用完整未来真值，因此只能用于回顾性离线挖掘；正式论文需要同时报告未筛选的自然分布组，不能将该标签解释为实时预警能力。

每个场景输出事件净车距、THW、接近速度、TTC、首次未来横向重叠时刻、可干预时间、首次重叠前向净间距、重叠期间最小纵向间距、原始未来最小车框间距，以及没有入选的逐项原因。测试 recording 被接口明确禁止读取。

## 运行

```bash
python -m scenario_reconstruction.conflict_diagnostics --manifest data/processed/highd_stratified_v2/manifest.json --config configs/conflict_diagnostics.json --splits train validation --output data_analysis/raw_data/conflict_diagnostics_v1
```

输出目录必须为空。逐场景记录和完整汇总保存在被 Git 忽略的本地目录，只提交不包含原始轨迹的精简汇总 `results/conflict_diagnostics_summary.json`。

## 首轮结果

180 个 train/validation 场景、15 个 recording 中，共有 7 个场景、5 个 recording 满足全部条件：训练集 5/120，验证集 2/60；7 个场景全部属于 `short_closing`。原始轨迹中没有目标车辆未来碰撞，入选场景的最小原始未来车框间距为 6.47 m。

最常见的排除原因是横向重叠期间纵向间距大于 15 m（161/180），其次是事件时没有足够的正接近速度（104/180）。各原因可以重叠，不能相加作为淘汰场景总数。结果说明此前零近失首先受到自然场景冲突强度限制，而不只是搜索器选择目标错误。

下一步应只在 train 和 validation 上运行可达性上界搜索：先用较大预算 CEM 检查这 7 个场景在正式物理边界内能否碰撞，再对全部自然分布场景保持同样搜索，以避免只报告筛选后的有利结果。测试集继续封存。
